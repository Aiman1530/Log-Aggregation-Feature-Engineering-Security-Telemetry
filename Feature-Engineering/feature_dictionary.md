# Feature Dictionary

This document explains the features generated by the Security Feature Extractor.

| Feature Name | Type | Description |
|--------------|------|-------------|
| window_id | String | Unique ID created from the date and hour of the aggregation window. |
| user_hash | String | SHA-256 hashed user ID used to protect user privacy. |
| date | Date | Date of the security events. |
| hour | Integer | Hour extracted from the timestamp (0–23). |
| event_count | Integer | Total number of events in the selected window. |
| login_success_count | Integer | Number of successful login events. |
| login_failure_count | Integer | Number of failed login events. |
| unique_source_ips | Integer | Number of different source IP addresses used by the user. |
| failure_ratio | Float | Failed logins divided by the total login attempts. |
| success_rate | Float | Successful logins divided by the total login attempts. |
| time_since_last_login | Float | Time in minutes since the user's previous login. |
| is_business_hours | Boolean | True if the event occurred between 9:00 AM and 6:00 PM. |
| bytes_transferred | Integer | Total number of bytes transferred during the selected window. |
| unique_dest_ports | Integer | Number of different destination ports accessed. |
| domain_length | Integer | Number of characters in the DNS query domain. |
| dns_query_entropy | Float | Shannon entropy of the DNS query, used to identify unusual domain names. |
| peer_deviation | Float | Z-score showing how different a user's transferred bytes are compared to the average. |
| privacy_risk | String | Privacy risk level (LOW, MEDIUM, or HIGH). |


## Missing Values

Missing values are handled before feature extraction.

- Text values are replaced with **"Unknown"**.
- Numeric values are replaced with **0**.

This keeps the output complete and prevents errors during processing.


## Rolling Windows

The feature extractor supports rolling windows of:

- 1 hour
- 4 hours
- 24 hours

A rolling window looks at events from the previous time period instead of only the current hour.

For example, if the current event happened at **2:30 PM**, then:

- **1-hour window** includes events from **1:30 PM to 2:30 PM**
- **4-hour window** includes events from **10:30 AM to 2:30 PM**
- **24-hour window** includes events from the previous 24 hours

This helps capture recent user activity and behavior trends, which can improve machine learning models.
